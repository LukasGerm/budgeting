# Issue 04 — translate core app (Lingui v6)

Surfaces wrapped in macros: app shell, home, spend (entry-form/spend-sheet/numeric-keypad), history (expense-row), dashboard (`components/dashboard/*`), habits. English is source; German catalog at `src/locales/de/messages.{po,ts}`, "du" register.

## BLOCKER discovered: `pnpm extract` / `pnpm compile` silently no-op
**Why:** Lingui CLI 6.1.0 guards its entire command body behind `if (import.meta.main)` (`node_modules/@lingui/cli/dist/lingui-extract.js:91`, same in `lingui-compile.js`). `import.meta.main` is `undefined` on Node v22.15.0 (repo's `.nvmrc` pins 22), only truthy on Node ≥ ~22.18 / 24. So the CLI loads, the guard is falsy, nothing runs, exit 0, zero output — looks like success, refreshes nothing.
**How to apply:** This is an ENV fix (bump Node to ≥22.18 or pin a Lingui patch without the guard), NOT feature code. The committed catalogs were generated by throwaway `/tmp/*.mjs` scripts and ARE valid (the babel extractor `extractFromFileWithBabel(filename, codeString, onMsg, {}, {plugins:['typescript','jsx']})` works fine when called directly). To verify catalog↔code consistency without the CLI: walk `src`, run the extractor per file, diff message IDs against `JSON.parse` keys in the compiled `messages.ts`. Issues 05/06 are blocked until the pnpm scripts actually run.

## The English-word-passthrough trap (the #1 thing to check on any i18n slice)
When a `<Trans>` interpolates a **word-valued** placeholder whose value is a raw English string literal/union, the English word renders inside the German sentence.
- **Confirmed instance:** `vs-last-delta.tsx` `dirSpan = <span>{direction}</span>` where `direction: "less"|"more"|"same"` (from `domain/dashboard.ts`). Catalog `"{pctSpan} {dirSpan} als letzten Monat bisher"` → German user sees "40% **less** als letzten Monat". The "same" branch is fine (whole-sentence `<Trans>`).
- **Fix pattern:** branch into fully-translated whole sentences per direction (like the over/under-budget split in `projection-caption.tsx`, or the over_budget/on_track split in `index.tsx`), so the word is never a passthrough placeholder.
- **Why tests missed it:** `vs-last-delta.test.tsx` only renders `"en"` and asserts `toContain("less"/"more")` — passes in English, blesses the bug. **A `de` test would have caught it.** Lesson: per-locale tests must include a `de` case for any direction/word-valued interpolation, not just `en`.

## Patterns that were done RIGHT (bless these, don't re-flag)
- `t` always from `useLingui()` (component scope, locale-aware) for toasts/aria-labels/placeholders/computed handler strings; never module-scope `t`. Pre-compute labels at top of render before Recharts formatter callbacks (`habit-heatmap.tsx`, `pace-line-chart.tsx`, `monthly-trend-chart.tsx`) — no hooks in callbacks.
- `habit-streak-badge.tsx` uses two `t` literals (singular/plural ternary) instead of `<Plural>` due to a TS type conflict — both German forms correct ("Tag"/"Tage"). Acceptable; leaves an orphaned `n62Agu` plural ID in the catalog (harmless drift).
- Plurals via `<Plural one=... other=.../>` (headline-stats days-left, expense-row days-ago). DE "vor # Tag(en)" correct.
- Month abbreviations / dates are locale-aware via `useFormat().formatDate(date,"short"/"long")` (Module B), not hardcoded de-DE.
- `numeric-keypad` "." glyph intentionally locale-independent (keypad only emits ".").

## Test infra
`src/i18n/test-utils.tsx` → `renderWithI18n(locale, currency, node)` wraps `I18nProvider` (fresh `setupI18n()` per render — good isolation) + `LocaleContext`. Import `render`/`renderWithI18n` from here, not `@testing-library/react`, for any `<Trans>`/`useLingui`/`useFormat` component. `vitest.config.ts` adds `lingui()` + `babel({presets:[linguiTransformerBabelPreset()]})` mirroring `vite.config.ts`.
