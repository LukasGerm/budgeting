Authed shell chrome (`src/routes/_authed.tsx` + `src/components/bottom-nav.tsx`). Verified PASS 2026-05-30 (Habit-Tracker Slice 2 nav refactor), dashtest@example.com.

- **Bottom nav = exactly 4 tabs: Home · Dashboard · History · Habits.** Settings is NO LONGER a bottom tab. Order/labels stable. Home is exact-match active, others prefix. Tab links carry `aria-label` = label.
- **Settings moved to a gear** in a sticky top app-bar (`<header sticky top-0 z-30>`), rendered by `_authed` layout. The gear is `<Link to="/settings" aria-label="Settings">` (lucide Settings icon) — in `read_page`/`find` it shows as `link "Settings" href="/settings"`. It's in its OWN in-flow row above `<Outlet/>`, NOT fixed/overlapping. Present on Home, Dashboard, History, Habits; ABSENT on /onboarding (gated on `pathname !== "/onboarding"`, same flag hides the bottom nav).
- **No collision on Home:** gear sits in the top bar row (above a border divider); the StreakChip (🔥 N, a `button` with aria-label "Restraint streak: N days…") sits in the page's own `<header>` below the divider. Distinct rows, comfortable gap — verified via zoom of top-right region [588,0,1176,240]. The big centered "Available today" amount stays centered/uncramped.
- **Both gear and page headers are constrained to `max-w-md` centered.** So on a WIDE desktop viewport the gear is at the centered column's right edge, not the raw viewport edge — this is intentional (source comment). On a real ~390px phone it lands at the screen's right edge.
- **/habits (FULL feature, all 7 slices verified PASS 2026-05-31, fresh acct):** empty state = header "Habits" + "Track your daily routines." + CalendarCheck icon + "No habits yet" + "Build streaks…" + blue "Create your first habit" CTA. With habits: a "Today" checklist card (one row/habit: icon · name · 🔥streak · checkbox) ABOVE per-habit cards. Each card = icon+name, 🔥streak badge, ⋯ menu (Edit / Delete-in-red), and a GitHub-style heatmap (7 weekday rows × ~18 week cols ≈ 4mo, newest week RIGHT, today=top-right cell with white ring). Heatmap fits card width, NO horizontal scroll (grid inset from card edges; future cells in current week simply not rendered → not tappable). Create via "Create your first habit" CTA or the blue + FAB → "New habit" bottom-sheet (Name field + 16-icon grid; Create disabled until name). Auto-assigned distinct color per habit in creation order (1st=coral/red, 2nd=amber, 3rd=yellow). Cards/checklist in stable creation order (oldest first).
  - **Toggle/sync:** tapping a heatmap cell or a checklist checkbox is optimistic+instant and TWO-WAY synced (cell fill ↔ checkbox ↔ streak all agree, optimistically and after reload). Past cells backfill; double-tap = no error/glitch, ends consistent. All state SSR-persisted on hard reload (no loading flash). Edit changes name+icon in place, **color + streak/history immutable**; reopening Edit shows the NEW values (stale-prefill bug FIXED). Delete → confirm AlertDialog ("Delete this habit?", Cancel/Delete); confirm removes card + checklist row + history (no orphans on reload).
  - Hard reloads of /habits across the whole flow: ZERO console errors (no #418/#423, no UNAUTHORIZED), dev-server log clean.
- Hard reload of /habits AND /, plus nav across all routes: ZERO console errors/warnings (no #418, no UNAUTHORIZED), dev-server SSR log clean. Home hard load renders fully server-side (greeting+streak+amount+recent, no Loading/NotFound flash).

**Viewport caveat:** the chrome-MCP gives no viewport-resize tool, and AppleScript window-resize times out (permission prompt — don't push it). `read_page` reported viewport 758x667 while `computer screenshot` images are 1176px wide (DPR mismatch); the app's max-w-md layout means desktop width is still representative for nav/gear behavior, but a true scroll-stick demo of a long list isn't possible when content fits the tall desktop viewport (History's ~5 entries didn't overflow → scroll was a no-op).
